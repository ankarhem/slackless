## Edits made to api-files.md

1. **upload_url POST, Response.** The "non-200 is a failure" rule is now cited to clack (client.go:893-897) and the files.getUploadURLExternal docs ("a non-200 response indicates a failure"). It also notes that slackgo fails only on status >= 400 (beeper/slackgo/files.go:503-505).
2. **files.getUploadURLExternal, Transport.** Added that legacy wee-slack also sends this call as GET with a query string (wee-slack/wee-slack@2.x/wee_slack.py:6340-6347,1505-1507).
3. **files.completeUploadExternal, Transport (fixes a FAIL).** Replaced "POST form (wee-slack)" with three facts: the docs allow POST with a form or JSON body, emacs-slack POSTs JSON, and wee-slack sends a GET to `https://api.slack.com/api/<method>?<params>` with no body (wee_slack.py:6421-6434, 1498-1507, 967-983).
4. **url_private GET, auth (fixes a FAIL).** Split the host rule by client:
   - slackgo sends credentials only to https URLs on exactly files.slack.com (misc.go:293).
   - emacs-slack sends them to any https host containing "slack" (slack-request.el:402-418,445-464).
   - Legacy wee-slack's download has no host check. This replaces the wrong citation `wee-slack/wee-slack/slack/slack_api.py:66-71` with `wee-slack/wee-slack@2.x/wee_slack.py:4265-4273,1528-1539`.
5. **url_private GET, Used for.** "For a deleted-but-public file" is now the condition the source actually checks: the file has no url_private_download or url_private but has permalink_public (mautrix from-slack.go:347-353,386-399).
6. **files.sharedPublicURL, Response.** Removed `"public_url_shared": true` from the excerpt and moved it to LEADS as "unverified", because the cited docs example shows `false`.
7. **Cross-area methods.** Corrected the `saved.add` / `saved.delete` citation from manage.go:355-356 to manage.go:347,356.
